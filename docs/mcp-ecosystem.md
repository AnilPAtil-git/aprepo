# MCP ecosystem references

Checked 2026-10-15 against the primary documentation and project repositories
linked below. This selected survey covers reverse engineering, application
editors, browsers, debuggers, traffic, and development tools relevant to REA;
it is not a complete directory of MCP services. Each row identifies an implementation, so official
and community servers for the same application appear separately.

The capabilities below are upstream claims reviewed from documentation. No
listed server was installed, connected, or benchmarked for this survey. The REA
column describes source checkpoint `6688ed6db`; an upstream reference does not
establish REA compatibility or authorize integration.

The survey contains **30 implementations: 18 official/upstream-maintained and
12 community implementations**. Browse [analysis and debugging](#official-and-upstream-maintained-analysis-servers),
[editors and design](#official-editor-and-design-integrations),

## Version and interpretation notes

- **IDA:** the official server and `mrexodia/ida-pro-mcp` are separate contracts.
  The community maintainer's recommendation does not prove a drop-in migration
  for REA. Keep the [current compatibility profiles](ida-provider.md#supported-upstream-versions)
  authoritative until the replacement is verified.
- **Binary Ninja:** its documentation lists GUI MCP for every GUI edition,
  including native Windows. Headless MCP is listed for Commercial/Ultimate on
  macOS and Linux; native Windows packages do not yet include that executable.
  Session-scoped handles and the active BinaryView are significant to target
  identity. [Upstream guide](https://docs.binary.ninja/guide/mcp.html).
- **JEB:** current upstream documentation describes `-c --mcp`, while the
  [REA guide](jeb-analysis.md#bring-your-own-engine) records that this route was
  unavailable in its JEB 5.48 verification. This documentation/runtime discrepancy
  remains unresolved here; follow the recorded GUI or programmatic route rather
  than replacing tested instructions from a web search alone.
  [Upstream startup instructions](https://pnfsoftware.com/jeb/manual/mcp/).
- **WinDbg:** Microsoft's setup guide requires version `1.2610.1001.0` or
  later. The proxy selects the sole available session automatically; multiple
  sessions require explicit selection. This is not an installed-client
  verification. [Setup requirements](https://learn.microsoft.com/windows-hardware/drivers/debuggercmds/set-up-windbg-mcp).
- **LLDB:** the cited upstream documentation describes a native server, but this
  survey did not establish which packaged LLDB distributions include it.
  Discovery of other interactive instances occurs when `lldb-mcp` starts.
  Closing an interactive session owned by a person is refused; debuggee output
  is not returned as debugger output. [Upstream lifecycle details](https://lldb.llvm.org/use/mcp.html).
- **dnSpyEx extension:** the README labels its commands read-only, then lists
  `Update_Method_SourceCode`, `Set_Function_Opcodes`, and renaming operations.
  It also mentions different HTTP ports and wildcard listeners. These are
  conflicting upstream descriptions, not tested guarantees of safe defaults.
  [Source README](https://github.com/AgentSmithers/DnSpy-MCPserver-Extension).
- **Client support is not a server:** Android Studio's
  [Add an MCP server](https://developer.android.com/studio/gemini/add-mcp-server)
  page describes Gemini consuming external servers. That page alone does not
  establish an Android Studio server that external agents can drive.

For REA development, public operations still follow the [tool design guide](tool-design.md),
[MCP contracts](mcp-contracts.md), and
[contribution scope](https://github.com/morluto/rea/blob/main/CONTRIBUTING.md#contribution-scope).
This survey adds references, not provider registrations or installation steps.
